1. Using your Book class as the example, explain what encapsulation buys you here that a class with public fields would not.

Encapsulation keeps the fields of the Book class private so they cannot be changed directly from outside the class. Getters and setters control how the data is accessed or modified, allowing validation such as preventing a negative price.

2. Explain the difference between a class and an object, again anchored in your Book example.

A class is a blueprint that defines the properties and behavior of an object. For example, Book is a class, while a particular book such as Clean Code created using new Book(...) is an object.

3. Why did we make totalBooks static instead of an instance field? What would go wrong if it weren't static?

totalBooks is static because it represents the total number of books shared by all Book objects. If it were an instance variable, every book would have its own separate counter instead of one common count.
